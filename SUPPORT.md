# Studydeck Support

Start with the [README](README.md) for installation, storage, backup, and architecture information.
Development and contribution guidance lives in [CONTRIBUTING.md](CONTRIBUTING.md).

## Questions and problems

Use [GitHub Issues](https://github.com/AUser3/study-deck/issues) for usage questions and reproducible
bugs. Before opening an issue, check whether an existing issue already covers the same problem.

For a bug, include:

- the Studydeck version or commit;
- your operating system, Node.js version, and whether you are using WSL;
- clear steps to reproduce the problem;
- the expected and observed behavior; and
- relevant logs with personal data and secrets removed.

Back up your Studydeck data before following troubleshooting steps that could change it.

## Feature requests

Open a GitHub issue describing the problem you want to solve, who it affects, and the smallest useful
outcome. A focused use case is more useful than a proposed implementation with no demonstrated need.

## Security issues

Do not report vulnerabilities through a public issue. Follow the private reporting process in
[SECURITY.md](SECURITY.md).
